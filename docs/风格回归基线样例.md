# 风格回归基线样例（原始转写 vs 整理稿）

> 文档定位：为"口述风格还原度"建立可回归对照的样例基线。
> 关联审查项：P3-B（#5 节 "原始转写 vs 整理稿" 对照样例）。
> 配套功能：整理时可在 `PolishView` / 记忆处理 / 章节草稿生成处选择「校订·保真」或「文学化改写」两档（见审查清单 P3-C）。

## 〇、为什么需要这个基线

口述史的核心张力是：**"整理"既可能修正错误、提升可读性，也可能误伤口述者特有的语气、方言与口头禅，丢掉真实感。**
本基线用"原始转写 → 整理稿"成对样例，把"口述风格还原度"从主观判断变成可对照、可回归的检查项：

- 新增/调整提示词后，拿样例走一遍，肉眼核对输出是否"在该保真的地方保真、在该创作的地方标注创作"。
- 积累真实录音后，把样例替换/扩充为真实语料，作为风格回归的金标准。

## 一、样例格式（schema）

每条基线 = 一个 `case`，字段如下：

```yaml
- id: CASE-001            # 唯一编号
  tier: faithful|creative # 对应整理档位
  scenario: 简述场景        # 如"老人回忆童年""老兵讲述战场"
  source: |                # 原始转写（尽量保留口语特征）
    ...
  expected: |              # 期望的整理稿（人工评审确认）
    ...
  notes: 该 case 重点考察什么（保留语气词 / 不虚构 / 标注创作 等）
```

> 约定：`source` 必须"脏"得真实（含语气词、重复、半句、方言）；`expected` 必须"干净但不失真"。
> 本文件中的 `source/expected` 为**示意性虚构示例**，仅用于说明格式与判定标准，正式基线请用真实脱敏语料替换。

## 二、校订·保真（faithful）样例

**判定标准**：只修错别字/明显语病，**保留**口述者的语气词（嗯、啊、那个、然后）、方言、口头禅与自然停顿；不文学化、不删口语特征。

### CASE-F01 · 保留口头禅
```yaml
- id: CASE-F01
  tier: faithful
  scenario: 老人讲述童年赶集
  source: |
    那个……嗯，我跟你讲，那会儿啊，我们赶集都是走路去的，走啊走啊，走大半天，那个脚都肿了。
  expected: |
    那个……嗯，我跟你讲，那会儿啊，我们赶集都是走路去的，走啊走啊，走大半天，那个脚都肿了。
  notes: 原始转写已通顺，仅应保留原貌；除非有错别字，否则不应删"那个/嗯/啊"等口癖。
```

### CASE-F02 · 仅修错字不动口吻
```yaml
- id: CASE-F02
  tier: faithful
  scenario: 讲述一段农事
  source: |
    等到麦子黄了，我们就开使收割，呃，那时候哪有机器，全是手工割的。
  expected: |
    等到麦子黄了，我们就开始收割，呃，那时候哪有机器，全是手工割的。
  notes: "开使"→"开始"是唯一应修正处；"呃""哪有"等口语特征必须保留。
```

### CASE-F03 · 方言保留
```yaml
- id: CASE-F03
  tier: faithful
  scenario: 方言区口述
  source: |
    佢哋细个嗰阵，朝朝早起身去抌草，好鬼辛苦嘅。
  expected: |
    佢哋细个嗰阵，朝朝早起身去抌草，好鬼辛苦嘅。
  notes: 粤语等方言词汇是口述者身份的一部分，保真档不得"翻译"成普通话。
```

## 三、文学化改写（creative）样例

**判定标准**：允许润色、删冗余、叙事重组与画面感增强；但**核心事实不变**，且输出应被明确视为"创作性结果"（UI 会标"创作性"徽标，生成后提示核对事实）。

### CASE-C01 · 润色增强画面感
```yaml
- id: CASE-C01
  tier: creative
  scenario: 同上赶集记忆
  source: |
    那个……嗯，我跟你讲，那会儿啊，我们赶集都是走路去的，走啊走啊，走大半天，那个脚都肿了。
  expected: |
    我至今记得，那年赶集全靠一双脚。天不亮就出门，一路走一路聊，等到了集镇，脚背早已肿得发亮。
  notes: 去掉口语填充词、重组为文学化叙述；但"走路去/走大半天/脚肿"等核心事实不得改写。属创作性结果。
```

### CASE-C02 · 重组但不虚构
```yaml
- id: CASE-C02
  tier: creative
  scenario: 农事回忆
  source: |
    等到麦子黄了，我们就开使收割，呃，那时候哪有机器，全是手工割的。
  expected: |
    麦浪泛黄时，收割便开始了。那是个没有机器的年代，镰刀起落，全凭一双手。
  notes: "开使"在创作档可顺带修正为"开始"；不得添加"亩产多少""和谁一起"等原文没有的事实。属创作性结果。
```

## 四、如何用本基线做回归

1. **提示词改动后**：把每个 `source` 喂给对应档位的整理命令，对比输出与 `expected` 的"保真/创作"取向是否一致。
2. **新增真实语料**：在 `data/` 或本目录追加 `CASE-` 条目，替换示意示例；建议脱敏（隐去真实姓名/地名或使用化名）。
3. **判定清单（每条必查）**：
   - 保真档：错别字/语病是否已修？口癖/方言/停顿是否保留？有无被偷偷"文学化"？
   - 创作档：核心事实（时间/地点/人物/事件）是否与 `source` 一致？有无凭空编造？是否标注为创作性结果？
4. **不通过的处理**：回到 `src-tauri/src/llm.rs` 的 `process_text` 与 `src-tauri/src/lib.rs` 的章节草稿提示词，按档位微调，再跑基线。
