# 移动记录端复审与发布说明

日期：2026-09-19。审查依据：`移动端网页记录与桌面资料库改造计划.md`。

## 结论

原有 A–C 实现具备基本产品结构，但不能按旧交接文档直接验收。发现并修复了备份格式不匹配、恢复路径不可迁移、旧素材覆盖新内容、导入非事务、录音异步保存竞争、切页丢失录音状态等问题。D 的离线资源与中断处理、E 的发布准备已补充；真机和 Windows 完整交互验收仍未完成，不能标记整个计划已验收。

## 本轮修改

- 完整备份：统一二进制 SHA-256 格式；从一致性快照收集音频；缺失音频时拒绝伪完整备份；独立包内文件名避免同名覆盖；检查清单、重复路径、越界长度和截断尾部。恢复先准备独立音频目录、校验数据库并重写资产及转写任务路径，最后通过 SQLite backup API 提交；恢复前保存一致性数据库副本。
- 素材包：按资料库、来源 ID、revision 和内容指纹记录导入凭据；同内容重复导入跳过，同修订不同内容也保留双方；禁止用旧包覆盖当前编辑。整包数据库事务，失败可重试。人物、标签、多音频和待转写任务全部登记。音频文件名由本机生成，阻止包内路径操纵写入位置。预览与实际导入采用同一判定。
- 桌面录音：原 PCM 和恢复标记保留至成功入库；登记失败后可恢复；清理保护待入库 WAV；录音初始化失败会等待写入线程退出。恢复过程仍保留原有平台音频流实现，Windows 麦克风长时间压力测试待做。
- 编辑：增加记忆和章节未保存时跨区域导航确认；修复切换不同章节但正文相同的刷新依赖。版本删除的 SQL 改为 bundled SQLite 可用的子查询写法。
- 手机录音：切换导航不卸载录音组件；分片顺序落盘，结束等待写入；最终音频、记录和恢复标记清理采用同一 IndexedDB 事务；恢复使用稳定 ID；未完成录音禁止覆盖；错误和设备结束停止计时；切后台主动暂停；恢复先检查连续分片和浏览器可解码性，失败保留分片。解码成功不等于音频尾部完整，仍需用户试听。
- 手机导出：缺失音频时拒绝不完整包；超过 256 MiB 要求分批；下载状态显示“已发起导出”，不宣称电脑收到。
- PWA：Manifest、图标、独立显示、带版本缓存及更新提示；显式缓存 mobile.html；更新等待旧窗口关闭，不强制刷新；离线缓存不碰 IndexedDB；提供 iPhone 安装、存储和系统录音备用说明。
- 发布：独立 `dist-mobile` 只带网页及字体/图标，不复制 public 中的开发证书；桌面资源明确包含转写、探测、转码脚本及 requirements；发布版写诊断日志；支持 `SHENGWEN_PYTHON` 并检查 faster-whisper/PyAV 导入，不把复制 venv 当作独立运行时。

主要源码：`src-tauri/src/{backup,pack_import,library,recorder,stt,lib}.rs`、`src/mobile/`、`src/components/LibraryView.tsx`、`src/hooks/useUnsavedGuard.ts`、`vite.config.ts`、`src-tauri/tauri.conf.json`。

## 构建与运行

手机构建：在项目根目录执行 `node tools/build-mobile.mjs`（也可 `npm run build:mobile`）。仅部署 `dist-mobile`，入口是 `mobile.html`。本机预览：`node node_modules/vite/bin/vite.js preview --outDir dist-mobile --host 127.0.0.1 --port 58125`。

手机使用必须是可信 HTTPS 地址。生产域名和托管平台尚未选定，因此未对外部署。不要上传整个仓库。缓存更新必须保留旧版带哈希资源一段时间，HTML、Manifest 和 mobile-sw.js 建议 `Cache-Control: no-cache`，带哈希资源可长期缓存。使用专用域名或专用子路径；更换协议、主机、端口均属于不同存储来源，先从旧地址导出。

桌面可执行程序需要 Windows WebView2，以及安装好 `faster-whisper` 和 `av` 的外部 Python；模型仍需下载或选择现有模型。设置进程环境变量 `SHENGWEN_PYTHON` 为该 Python 的绝对路径可避免误选环境。检查命令：`powershell -File tools/check-runtime.ps1 -Python <python.exe绝对路径>`。程序与 `resources/python_stt` 必须一起分发，不能只拷贝 EXE。

发布版资料使用 `%APPDATA%/com.voice-to-essay.app` 下的 sounds、models、data；这是当前仓库已有行为，开发版仍使用工程目录。发布版日志使用 Tauri 标准应用日志目录，Windows 通常是 `%LOCALAPPDATA%/com.voice-to-essay.app/logs`，文件前缀 shengwen。日志可能含文件路径，不含设计上主动记录的口述正文，分享前仍应检查。

## 已知限制与待完成验收

- 完整备份当前约 1 GiB 上限，素材包读取 512 MiB 上限，手机导出预检 256 MiB。当前归档仍以内存读取为主，不适合多年海量资料；超限须保留目录副本，后续需要流式归档。不要把限制理解为可以删除原始资料。
- 旧错误格式 `.svbak` 不自动修复，请用新版重新备份；首次导入没有凭据的旧手机记录可能产生一次保守冲突副本，此后按新凭据去重。
- 素材包导入失败时，事务回滚，但已经复制的未引用音频保留以避免误删；恢复失败时准备目录保留，需检查后处理，不自动清理。
- 恢复资料库属于整体替换，操作前停止录音、转写和 AI 整理。当前尚未完成所有后台写入与恢复的全局互斥验证，不建议工作进行中恢复。
- iPhone Safari/主屏幕、Android、真实麦克风、来电、锁屏、强制退出、存储不足与长录音均待真机验证。浏览器回归不代表这些通过。
- Windows 新目录中的完整录音→导入真实 M4A→转写→AI→章节→Markdown 流程待人工验证；本轮未调用用户远程模型，不产生 API 费用。
- F 局域网传输仍按计划留到 E 验收之后。

## 用户验收步骤

1. 先用合成或不重要素材。手机联网打开固定 HTTPS 地址，添加到主屏幕；录 10 秒、暂停、继续、保存并播放。
2. 录音时切“我的素材”再回来，确认状态保留；切其他 App 后回到页面，确认暂停或明确错误，计时不虚增。
3. 分别测试刷新、锁屏、关闭标签页和强制结束；重新打开应看到恢复入口；恢复后试听，失败时不得丢弃原分片。记录 iPhone 型号、iOS 版本、Safari/主屏幕模式和恢复的秒数。
4. 开飞行模式，重新打开网页，新建文字及录音，保存、播放；联网后确认原资料仍在。
5. 导出一条及多条到“文件”，取消一次分享；取消不能显示成功。电脑导入同包两次应不重复，修改手机正文后再导入应保留冲突双方。
6. 在电脑校订、AI 整理、加入章节并导出 Markdown；检查历史来源仍可追溯。修改正文后切记忆、章节、资料库及设置，取消离开应保留编辑。
7. 完整备份后在独立测试资料库恢复，检查音频播放、文字和版本关系；不要先在唯一真实资料库上试恢复。

每项记录“预期/实际/截图或日志/是否通过”。未通过项继续修复；上述真机与交互测试完成前，D2/E3 保持“实现中，待设备验收”。
