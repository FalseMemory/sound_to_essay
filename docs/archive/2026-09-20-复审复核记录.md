## 二、被复核方修正的两个真实缺陷（予以确认）

1. **保存非原子**
   原实现为 `putAudio → put(memory) → clearPendingRecording` 三步，中途崩溃会残留 pending 标记，
   导致下次进入记录页误报「发现未完成录音」。
   新实现 `commitRecording(memory, blob, recordingId)` 用**单个 IndexedDB 事务**同时写
   memories + audio、删 chunks、条件删 pending。**这是正确修法。**

2. **分片写入竞争**
   原实现 `onChunk` 中直接 `void store.appendChunk(...)`，顺序不保证，清理也可能先于写入完成。
   新实现以 `writesRef` 串行化写入，并在清理前 `await writesRef.current`。**正确。**

## 三、复核发现的问题

### 1. 三个方法成为死代码（编译告警）
```

         `update_memory_from_pack` are never used
```
说明 B3 素材包导入逻辑已被重写，旧方法失去调用点。
**需要确认**：新导入逻辑的跨设备去重／更新语义与原实现等价（尤其是 `source_id` + `revision` 的判定），
然后清理死代码，或保留并注明原因。

### 2. `.svbak` 格式被废止，且本机从未有过备份
文档自述「旧错误格式 `.svbak` 不自动修复」。实际搜索本机（项目目录、Downloads、Desktop、Documents、
`%APPDATA%/com.voice-to-essay.app`）：

```
（未找到任何 .svbak 文件）
```

结论有两面：
- **好的一面**：该破坏性变更**未造成任何数据损失**。
- **需要正视的一面**：说明**从未真正做过完整备份**。建议尽快执行文档步骤 7 ——
  完整备份后在**独立测试资料库**验证恢复，不要拿唯一真实资料库试恢复。

### 3. 没有版本控制（当前最大的工程风险）
`no .git`。本轮与上一轮对 `backup` / `pack_import` / `library` / `recorder` / `stt` / 手机端 的
大规模改动**无法 diff、无法回滚、无法追溯责任**。任何后续回归都只能靠人工比对。
**建议立即 `git init` 并完成首次提交**，之后每轮改动单独提交。

### 4. 真机验收仍未执行（文档已如实声明）
文档明确写出未验收项：iPhone Safari／主屏幕、Android、真实麦克风、来电、锁屏、强制退出、
存储不足、长录音、Windows 新目录完整流程。并声明「生成 EXE 不等于完成 Windows 交互验收」、
「浏览器回归不代表这些通过」。**这一点没有夸大，予以肯定。**
