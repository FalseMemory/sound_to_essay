### 2. 浏览器运行路径完全不碰 Tauri

### 3. 建立存储、录音、导出适配接口

新增 `src/mobile/adapters/`：

| 文件 | 内容 |
| --- | --- |
| `types.ts` | `LocalMemory` / `LocalAudioAsset` / `MemoryStore` / `RecorderAdapter` / `ExporterAdapter` / `PlatformCapabilities` 等接口定义 |
| `storage.ts` | IndexedDB 实现（memories / audio / chunks 三个仓库） |
| `recorder.ts` | MediaRecorder 实现：**运行时探测格式**、权限错误翻译、开始/暂停/继续/结束、按 1s 切片产出分块 |
| `exporter.ts` | 系统分享（Web Share L2）优先，不可用回退文件下载；取消如实报告 |
| `hash.ts` | Web Crypto 的 SHA-256 |
| `index.ts` | 适配层入口，业务只从这里取能力 |

设计要点：
- `MemoryStore` 带 `appendChunk` / `listChunks` / `clearChunks`，为 C2 的「边录边存 + 中断恢复」预留。
- 录音格式**不假定 WebM/WAV**：按 `audio/mp4` → `audio/webm;codecs=opus` → `audio/ogg` → `audio/wav`
  顺序用 `MediaRecorder.isTypeSupported` 实测（iOS Safari 通常落 m4a，Android 落 webm）。
- 采样率取不到时**留空**，不猜默认值。
- `ExportResult` **刻意没有**「电脑已接收」状态——手机无从得知对方是否收到。

### 4. 移动端单栏布局与底部导航

- `src/mobile/App.tsx`：单栏 + 底部三 Tab —— **记录 / 我的素材 / 设置**。
- 记录页（`RecordView`）：录音是最突出操作，主按钮 128×128 px；
  状态机 `idle → recording ⇄ paused → saving → saved/error`，明确区分「保存中」与「已保存」；
  录音中离开页面有 `beforeunload` 提示。
- 我的素材（`MaterialsView`）：列表显示标题、时间、时长、格式、体积与保存状态；支持播放试听。
- 设置（`SettingsView`）：**如实说明**素材存在「此设备浏览器内」、清除浏览器数据会丢失；
  逐项展示本机能力（安全上下文 / 录音接口 / 麦克风 / 本机数据库 / 系统分享 / 探测到的录音格式 / 已用存储）。

### 5. 移动端适配

- `src/mobile/index.css`：复用桌面端设计 token，仅做移动端必要覆盖。
- 安全区：`.safe-top` / `.safe-bottom` 使用 `env(safe-area-inset-*)`，`viewport-fit=cover` 已在 `mobile.html` 声明。
- 触控目标：`.touch-target` 保证 ≥44×44 CSS 像素（计划要求），底部导航与主要按钮全部满足。
- 防横向溢出：`.wrap-anywhere` 用于长标题/长内容；布局全部使用 `min-w-0` + `truncate` 组合。
- 大字体：使用相对单位、不锁 `-webkit-text-size-adjust`，可跟随系统字号缩放。
- 第一版**不展示**桌面端的章节与旧创作区入口。

## 手机上录音需要 HTTPS —— 已提供本地自签方案

麦克风（`getUserMedia`）只在**安全上下文**可用，即 `https://` 或 `localhost`：

- 电脑访问 `http://localhost:57123/mobile.html` → 安全上下文 → 可录音
- 手机访问 `http://<电脑IP>:57123/mobile.html` → **非**安全上下文 → 录音不可用

已在设备上复现该现象，并做了两件事：

### 1. 报错说清真实原因（此前会误导）
原来只报"此浏览器不支持网页录音"，实际原因是**没走 HTTPS**。现已新增 `diagnoseRecording()`：
**先判安全上下文**，再判浏览器能力——避免把"没走 HTTPS"误报成"浏览器太旧"，害用户白换浏览器。

- 录音页**一进页面**就显示真实原因 + 解决办法（不再等点击后才报错）
- 不可录音时按钮置灰、状态显示「本机无法录音」
- 设置页复用同一套诊断

### 2. 提供本地自签证书方案（不依赖外网）

新增 `tools/make-dev-cert.ps1`：
- 首建本地 CA（**只创建一次**），用其签发服务器证书，SAN 自动纳入 `localhost`、`127.0.0.1` 与**当前**局域网 IP
- CA 证书发布到 `public/sound-to-essay-ca.crt` 供手机下载安装
- **IP 变化时重跑脚本即可**（CA 不变 → 手机无需重新安装）

`vite.config.ts` 增加 HTTPS 开关：默认仍是 `http:57123`（桌面端 `devUrl` 固定指向它，不可破坏）；
`VITE_HTTPS=1` 时以 `https:57124` 启动，**端口不同，两个服务可同时运行互不抢占**。

配套：
- `启动手机端HTTPS.bat`（双击即用）
- `docs/手机端HTTPS调试说明.md`（含 iPhone / Android 安装信任 CA 的完整步骤与常见问题）
- `certs/*.key` 已加入 `.gitignore`，私钥不入库

> 曾尝试 cloudflared 隧道（免手机装证书），但本机网络下 GitHub Release 二进制无法下载
> （直连 502、http 代理与 socks5 均 TLS 握手失败）。自签证书方案零外网依赖，更稳定。

设置页把「安全上下文」作为一项能力**如实展示**，不满足时说明原因，避免误判为程序故障。
