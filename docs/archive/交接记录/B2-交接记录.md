## 完成内容

### 1. 协议文档

- 新增 `docs/素材包协议.md`，定义素材包（`.svpack` / ZIP）的：
  - 容器格式（推荐 ZIP，允许等价容器）。
  - `manifest.json`：协议版本、包 ID、导出时间（带时区）、应用版本、记录/音频清单及逐文件 SHA-256。
  - `records.json`：稳定记录 ID（`recordId`）、修订标识（`revision`）、标题、正文、录音时间（带时区）、模糊事件时间（`eventDateText`/`eventDatePrecision` 独立保存）、人物、地点、标签、备注、音频条目（`assetId`/`originalFilename`/`sourceFormat`/`durationSecs`/`sampleRate`/`sha256`）。
  - 记录与资产的关联方式（`record.audio[].assetId` ↔ `manifest.audio[].assetId` ↔ 包内 `audio/<assetId>.<ext>`）。
  - 安全约束：不含本机绝对路径、API Key、账户配置、设备唯一标识；`.svpack` 不含数据库快照。
  - 导入语义（B3 依据）：按 `recordId` 去重；`revision` 大者为更新；冲突保留双方并提示；不传播删除；缺失音频不得伪装完整导入；SHA-256 仅用于完整性与去重，不构成身份认证。
  - 版本演进：`formatVersion=1`；未来新增字段必须可选，破坏性变更递增版本。

### 2. 明确区分"传输素材包"与"完整桌面备份"

- 协议文档 §1 明确：素材包是手机→桌面的**传输容器**，只含选定记录与音频；完整桌面备份（`.svbak`，A3）含整个 SQLite 一致性快照 + 全部音频，用于灾备。二者不可混用、不互相替代。

### 3. 稳定记录 ID 与修订标识

- `recordId`：uuid-v4，同一记录跨导出、跨设备不变。
- `revision`：整数递增，记录修改后保留 ID、更新 revision。
- 协议明确：同一记录重复导出 `recordId` 相同、`revision` 可能相同或更大；**不得**因内容变化换新 ID。

### 4. 测试样例

- 新增 `tools/make_pack_samples.py`：生成 4 个测试样例到 `tools/pack_samples/`。
- 新增 `tools/validate_pack_samples.py`：校验样例结构、SHA-256、异常路径。
- 样例清单：
  - `sample_pack.svpack`：2 条记录 + 2 个合成音频的最小合法包。
  - `corrupt_checksum.svpack`：manifest 中音频 SHA-256 被篡改（完整性失败路径）。
  - `unsupported_version.svpack`：`formatVersion=999`（版本拒绝路径）。
  - `missing_audio.svpack`：记录引用了包内不存在的音频（缺失音频路径）。
- 所有音频为合成正弦波、文本为合成内容，**无真实口述素材**。

### 5. 本机容器过渡说明

- 因本机缺少 C 链接器、无法引入 ZIP 库，桌面端样例与 B3 首版导入暂用自实现 `.svpack`（与 `.svbak` 同构的二进制容器）。
- **协议字段与 ZIP 版完全一致**，仅外层编码不同；B3 导入时按 magic 识别 `.svpack`、按 `PK\x03\x04` 识别 ZIP，归一化为同一内存结构后走同一套校验/导入逻辑。
- 未来在能链接的环境引入 ZIP 库后，`.svpack` 可废弃，协议字段不变。

3. 样例仅覆盖协议字段与异常路径，未覆盖超大包 / 大量记录的性能。
