## 任务编号

**A2．版本与来源保护**

## 完成内容

### 1. 原始转写受保护，普通"删除历史版本"删不掉

- `delete_text_version` 新增保护：目标版本是 `raw_transcription`（原始转写）时直接拒绝并说明原因。原始素材一旦丢失无法重建，因此必须保留。
- 前端版本列表对原始转写不再提供「删除」按钮，改为「受保护」徽标（悬停说明原因），从源头避免用户误删。
- 其余版本（人工校订、AI 整理等）仍可正常删除；删除确认文案已补充保护说明。

### 2. 恢复历史版本只切换指针，不制造重复版本

- **记忆文本版本**：`restore_text_version` 原本先清零 `is_current` 再检查目标版本是否存在——目标不存在时会留下"没有任何当前版本"的损坏状态。现改为**先在事务内确认目标版本存在**，再切换指针，并连同搜索索引更新在同一事务提交（满足"版本切换与搜索索引更新保持事务一致性"）。
- **章节草稿**：前端 `switchDraft` 旧实现是**新建一份内容相同的副本**（每次"恢复"都让草稿数量 +1），且副本没有继承来源。现改为后端新增 `restore_chapter_draft`，**只切换 `is_current` 指针**，不复制内容、不新增草稿，生成时的来源记录原样保留。
- 因此"连续恢复相同历史版本，版本数量不增加"对记忆版本与章节草稿都成立。

### 3. 删除当前章节草稿时明确接管

- `delete_chapter_draft` 改为事务：删除草稿与其来源记录；若删掉的是**当前草稿**，则把**剩余最新的一份**提升为当前；没有剩余草稿则进入"无草稿状态"（`is_current` 全为 0），绝不留下"章节没有当前草稿却又指着一个已删除 ID"的中间态。

### 4. 每次 AI 章节生成记录实际使用的来源与生成条件

- 新增表 `chapter_draft_sources`，在草稿创建时**与草稿同一事务**写入每条来源：记忆 ID、**生成时的记忆标题快照**、当时采用的文本版本 ID、版本类型快照、记录时间。
- 标题与版本类型由后端按 ID 回查后快照保存——记忆日后改名、版本类型变化，旧草稿仍能准确说明"当时用了什么"。
- `chapter_drafts` 新增 `requirement` 列，保存生成时的**写作要求**（风格提示词）。
- 后端 `ai_generate_chapter_draft` 在构建素材时**捕获每条记忆实际使用的当前文本版本 ID**，连同模型、处理档位、写作要求、生成时间一起落库。
- 前端草稿历史展示**生成时记录的来源**（记忆标题 + 版本类型 + 版本缺失标记）与写作要求，**读取的是来源表而非当前章节关联列表**——这正是计划要求的"旧草稿的来源展示读取生成时记录，不能用当前章节关联列表替代"。

### 5. 被历史草稿引用的文本版本不得硬删除

- `delete_text_version` 新增第二道保护：目标版本被 `chapter_draft_sources` 引用时拒绝删除并告知被几份草稿引用。删掉版本会让旧草稿的来源断裂，因此禁止。

## 数据库或协议变化

- `SCHEMA_VERSION`：3 → 4。
- 新增表（幂等，不破坏既有库）：

```sql
CREATE TABLE IF NOT EXISTS chapter_draft_sources (
  id TEXT PRIMARY KEY, draft_id TEXT NOT NULL REFERENCES chapter_drafts(id),
  memory_id TEXT NOT NULL, memory_title TEXT NOT NULL DEFAULT '',
  text_version_id TEXT, version_type TEXT, recorded_at TEXT NOT NULL
);
```

- 新增列（幂等 ALTER，列已存在时忽略）：`chapter_drafts.requirement TEXT`。
- 未删除或重命名任何既有表/列；既有草稿数据保留（其 `sources` 为空，因生成时未记录来源，属预期）。
- 未新增对外协议。

## 已知问题

1. **历史草稿无来源**：A2 之前生成的草稿没有来源记录，无法追溯当时输入。这是数据层面的既成事实，本任务无法回填。
2. **AI 生成只记录"当前版本"**：来源记录的是生成时各记忆的当前文本版本 ID；若生成后用户立刻改了文本，旧草稿来源仍指向生成那一刻的版本（这正是设计意图），但用户需理解"来源 ≠ 最新内容"。
3. **删除被引用版本的前端提示**：后端拒绝时前端会把原因显示在 notice 栏，但没有针对"被 N 份草稿引用"做专门的高亮样式。
