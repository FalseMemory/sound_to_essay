# 口述回归录项目 · 审查报告与待办清单

> 审查时间：2026-08-26
> 审查范围：仓库现状（代码 + 内容 + 文档一致性）
> 结论：**这是一个架构清晰、可编译通过的口述史/回忆录写作桌面应用（"声文 Voice to Essay"，Tauri+React+Rust+Python STT），但尚未产出《口述回归录》正文本身，且存在 1 个会导致功能失效的运行期缺陷、若干文档/仓库污染与规划未落地问题。**

---

## 〇、定位澄清（最重要）

本仓库**不是一份写好的《口述回归录》文稿**，而是用来**生产**回忆录的工具软件。关键证据：

- `lv_backup.txt` 读出来是 `LibraryView.tsx` 的**旧版源代码**，不是回忆录文本。
- 根目录 `write_lv.py` ~ `write_lv5.py` 文件名里的 "lv" = **LibraryView**；它们是上一任 AI 用 Python 字符串字面量**拼装 TSX 代码**的生成/打补丁脚本，并非文稿。
- `sounds/` 下只有 6 个录音 WAV，`data/oral_history.sqlite3` 是新库；仓库内**没有任何 .md/.txt 形式的回忆录正文**。
- `rewrite_app.py` 全文只有一个 `pass`，是死代码。

**含义**：若你期望的交付物包含《口述回归录》正文（文字准确性、口述风格还原度、章节结构等），这部分内容当前**缺失**，需由本应用（录音→转写→整理→成章）或人工撰写产出。下面"文本准确性/口述风格"维度的审查因此只能给出方法论建议，无法对具体文稿打分。

## 一、高优先级缺陷（影响可用 / 数据）

### 1. AI 章节草稿生成功能实际不可用（运行期必报错）⚠️
- 前端 `src/components/LibraryView.tsx:737` 调用：
  ```ts
  await invoke('ai_generate_chapter_draft', { chapterId: chapter.id, config });
  ```
- 后端 `src-tauri/src/lib.rs:473` 命令签名要求 4 个参数：
  ```rust
  async fn ai_generate_chapter_draft(
      state, chapter_id: String, memory_ids: Vec<String>, style: String, config: LLMConfig)
  ```
- **缺 `memoryIds` 与 `style` 两个必填参数** → Tauri invoke 会抛 "missing field" 错误，"AI 生成草稿"按钮点下去必失败。
- 后端实现还有逻辑瑕疵（`lib.rs:485`）：用 `list_projects()?.get(0)` 取**第一个项目**的全部记忆再按 `memory_ids` 过滤，而 `memory_ids` 又根本没传。正确做法应只取**该章节已关联的记忆**（`chapter.memories`），而非"第一个项目"。
- **修复方向**：前端补传 `memoryIds: chapter.memories.map(m => m.id)` 与一个 `style` 串（可取自设置或固定为空）；后端改为基于 `add_memory_to_chapter` 已关联的记忆构建素材，去掉"第一个项目"假设。

### 2. 仓库内存在"代码 vs 备份"不一致，维护风险高
- `lv_backup.txt` 比真实 `src/components/LibraryView.tsx` **落后约 180 行**，缺少章节草稿 / AI 生成 / 导出等整块 UI。说明"改了源码但备份没更新"，备份机制形同虚设。

### 4. 构建产物 `dist/` 被提交在仓库根
- 含 `index.html/js/css/svg`。应加入 `.gitignore`，不纳入版本管理。

## 五、文本准确性与口述风格还原度（用户重点，但当前无法打分）

- 因仓库内**无《口述回归录》正文**，无法评估错别字、语义偏差、章节结构、风格还原度。这是内容层面最大空白。
- 转写链路（faster-whisper + VAD + 幻觉抑制 + 繁转简）设计合理，但最终"口述风格还原"取决于 (a) 原始录音质量 (b) AI 整理是否被过度改写。
- **潜在冲突**：后端 `ai_polish` 提示词要求"删除冗余语气词（嗯、啊、那个…）"，而"还原口述风格"往往需**保留**口述者特有语气词/方言/口头禅。当前未区分「校订（保真）」与「文学化改写（创作）」两档，存在误伤真实口述感的风险。
- **建议**：积累真实录音+转写后，建立"原始转写 vs 整理稿"对照样例集作为风格回归基线；明确两档提示词，校订档保留口述特征，改写档才允许文学化并标注"创作性结果"。

## 八、建议的完善方向（总览）

1. **先止血**：P0 三项（修 AI 章节生成、清仓库、核删除确认）应最先做，成本低、收益高。
2. **再对齐**：用代码（尤其 `generate_handler!`）反向校正 README/DESIGN，消灭"文档说一套、代码做一套"。
3. **后补功能**：时间线、关联候选、整本导出按 DESIGN 阶段 C/D 顺序落地，且每步保留"AI 输出可追溯+矛盾可见"的硬约束。
4. **内容基线**：在真实录音/转写积累后，用对照样例集把"口述风格还原度"从主观判断变成可回归检查的项。
5. **开发纪律**：停止用 Python 字符串脚本生成 TSX；所有改动直接在源码上做，并以 `npx tsc -b --noEmit` + Rust `cargo build` 作为准入校验。
