## 二、第三方复审发现并修复的问题（2026-09-19）

| 领域 | 修复内容 |
| --- | --- |
| **完整备份** | 统一二进制 SHA-256 格式；从一致性快照收集音频；缺失音频时**拒绝伪完整备份**；独立包内文件名避免同名覆盖；检查清单/重复路径/越界长度/截断尾部。恢复先准备独立音频目录、校验数据库并重写资产与转写任务路径，最后经 SQLite backup API 提交；**恢复前保存一致性数据库副本**。 |

| **桌面录音** | 原 PCM 与恢复标记保留至成功入库；登记失败后可恢复；清理动作保护待入库 WAV；录音初始化失败会等待写入线程退出。 |

### 复核确认：两个被修正的真实缺陷

1. **保存非原子** —— 原为 `putAudio → put(memory) → clearPendingRecording` 三步，中途崩溃会残留 pending 标记，下次进入记录页误报「发现未完成录音」。新实现 `commitRecording()` 用**单个 IndexedDB 事务**一次完成。**修法正确。**
2. **分片写入竞争** —— 原 `onChunk` 中 `void appendChunk(...)` 未串行化，顺序不保证。新实现以 `writesRef` 串行化，并在清理前 `await`。**正确。**

### 复核发现的问题

1. **三个方法成为死代码**（编译告警）：`find_memory_by_source_id` / `set_memory_source` / `update_memory_from_pack` 从未被使用。
   说明 B3 导入逻辑已被重写。**需确认新逻辑的跨设备去重/更新语义与旧实现等价**，然后清理或注明保留原因。
2. **`.svbak` 格式被废止**（文档自述"旧错误格式不自动修复"）。实际搜索本机：**未找到任何 `.svbak` 文件**
   → 该破坏性变更**未造成数据损失**，但也说明**从未真正做过完整备份**。
3. **（已解决）无版本控制** —— 复核时 `no .git`，无法 diff/回滚。**2026-09-20 已建立 git 仓库并完成首次提交。**

## 五、已知限制

- **完整备份当前约 1 GiB 上限，素材包读取 512 MiB，手机导出预检 256 MiB。** 归档仍以内存读取为主，
  不适合多年海量资料；超限须保留目录副本，后续需要流式归档。**不要把限制理解为可以删除原始资料。**
- **旧错误格式 `.svbak` 不自动修复**，请用新版重新备份。首次导入没有凭据的旧手机记录可能产生一次保守冲突副本，此后按新凭据去重。
- 素材包导入失败时事务回滚，但**已复制的未引用音频保留**以避免误删；恢复失败时准备目录保留，需人工检查后处理，不自动清理。
- **恢复资料库属于整体替换**，操作前应停止录音、转写与 AI 整理。尚未完成所有后台写入与恢复的全局互斥验证，**不建议工作进行中恢复**。
- 手机端**导入音频不转码**：本机放不了的格式只能导出到电脑处理（刻意设计，避免在手机上引入解码依赖）。
- 导入素材的**录制时间不自动填写**（文件名无法可靠反映录制时间），需手动补充。
- 手机端仅支持 `.svpack` 容器（桌面端 ZIP 容器尚未实现）。
- 发布版需要**外部 Python**（已装 faster-whisper 与 av）与 Windows WebView2；程序与 `resources/python_stt` 必须一起分发，**不能只拷贝 EXE**。
- 日志可能含文件路径，不含设计上主动记录的口述正文，**分享前仍应检查**。

## 七、用户验收步骤

1. 先用合成或不重要素材。手机联网打开固定 HTTPS 地址，添加到主屏幕；录 10 秒、暂停、继续、保存并播放。
2. 录音时切「我的素材」再回来，确认状态保留；切其他 App 后回到页面，确认暂停或明确错误，**计时不虚增**。
3. 分别测试刷新、锁屏、关闭标签页、强制结束；重新打开应看到恢复入口；恢复后试听，**失败时不得丢弃原分片**。
   记录 iPhone 型号、iOS 版本、Safari/主屏幕模式与恢复的秒数。
4. 开飞行模式，重新打开网页，新建文字与录音，保存、播放；联网后确认原资料仍在。
5. 导出一条及多条到「文件」，取消一次分享；**取消不能显示成功**。电脑导入同包两次应不重复，修改手机正文后再导入应保留冲突双方。
6. 在电脑校订、AI 整理、加入章节并导出 Markdown；检查历史来源仍可追溯。
7. 完整备份后在**独立测试资料库**恢复，检查音频播放、文字与版本关系。**不要先在唯一真实资料库上试恢复。**

> 每项记录「预期 / 实际 / 截图或日志 / 是否通过」。未通过项继续修复；上述真机与交互测试完成前，
> D2 / E3 保持「实现中，待设备验收」。
