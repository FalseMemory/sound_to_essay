## 完成内容

### 1. 导入前预览

- 新增 `preview_pack` 命令：解析素材包 → 校验 → 返回记录数、音频数、重复项、冲突项、缺失音频数。
- 前端「导入素材包」区块：选包后显示预览（记录/音频/重复/冲突/缺失），点「导入此素材包」才执行。

### 2. 校验格式版本、文件存在性、大小与校验值

- `validate_pack`：校验 `formatVersion`（当前支持 1）、`records.json` 的 SHA-256 与大小、每个音频条目的存在性/大小/SHA-256。
- 解析 `.svpack` 时逐文件校验 SHA-256；任何不匹配即报错，不继续导入。

### 3. 使用临时区域组织导入

- 音频先写入临时目录（`sound-to-essay-pack-import-<uuid>`），校验通过后再复制到应用音频目录；完成后清理临时目录。
- 记忆登记走 `create_memory` 事务；音频资产与文本版本同事务写入。

### 4. 同一素材包重复导入不产生重复记忆

- `memories` 新增 `source_id` / `source_revision` 两列（幂等迁移），记录素材包的稳定记录 ID 与修订标识。
- 导入时按 `source_id` 去重：已存在且 `revision` 相同 → 跳过；已存在且本地 `revision` 更大 → 更新；冲突 → 保留双方。

### 5. 来源为手机的记录保留来源 ID 和修订信息

- 导入的记忆写入 `source_id`（= 包内 `recordId`）与 `source_revision`（= 包内 `revision`）。
- `find_memory_by_source_id` / `set_memory_source` / `update_memory_from_pack` 三个方法支撑去重/更新。

### 6. 缺失音频不伪装完整导入

- 记录引用的音频在包内缺失或校验失败 → 跳过该音频，不写入音频资产；导入结果统计 `missing_audio` 数，前端提示"N 个音频缺失未导入"。

### 7. 冲突保留双方并提示

- 本地 `source_revision` 小于包内 `revision` → 用包内内容更新本地（保留本地 ID，提升 `source_revision`）。
- 同 `revision` 但内容不同 → 本地不动，包内记录作为新记忆导入（标题加"（冲突副本）"），结果统计 `conflicts_kept_both`。

### 8. 不传播删除

- 素材包只携带"要传输的记录"，导入只追加/更新，不携带也不执行删除指令。
