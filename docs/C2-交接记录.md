## 任务编号

**C2．录音与本地保存**

## 完成内容

### 1. 录音格式运行时探测（不假定 WebM / WAV）

`src/mobile/adapters/recorder.ts` 按优先级用 `MediaRecorder.isTypeSupported` 实测：

```
audio/mp4;codecs=mp4a.40.2 → audio/mp4 → audio/webm;codecs=opus → audio/webm
→ audio/ogg;codecs=opus → audio/ogg → audio/wav
```

- iOS Safari 通常落在 `audio/mp4`（`.m4a`），Android Chrome 落在 `webm/opus`。
- 全部不支持时返回 `null`，由上层如实报错，**不假装支持**。
- **采样率取不到就留空**，不猜默认值。

### 2. 麦克风权限与设备异常的处理

`describeMediaError()` 把浏览器异常翻译成可执行的中文原因：

| 浏览器异常 | 用户看到 |
| --- | --- |
| `NotAllowedError` / `SecurityError` | 麦克风权限被拒绝，去地址栏权限设置里允许后重试 |
| `NotFoundError` | 没有检测到可用的麦克风设备 |
| `NotReadableError` / `TrackStartError` | 麦克风被其他应用占用，或系统拒绝了访问 |
| `OverconstrainedError` | 当前设备无法满足录音参数要求 |
| 其他 | 带上原始 message，不吞掉细节 |

另外 `diagnoseRecording()` **先判安全上下文**再判浏览器能力——避免把「没走 HTTPS」误导成「浏览器太旧」
（详见 `docs/手机端HTTPS调试说明.md`）。

### 3. 开始 / 暂停 / 继续 / 结束 + 时长显示

- 状态机：`idle → recording ⇄ paused → saving → saved`（或 `error`）。
- 暂停期间**不计入时长**（`foldSegment()` 把已录段落累加后再冻结）。
- 界面上「正在录音 / 已暂停 / 正在保存 / 已保存 / 出错了」严格区分。

### 4. 音频分块持续保存到 IndexedDB（本轮核心）

- 录音以 **1 秒为切片**（`TIMESLICE_MS`），每个分片立刻 `store.appendChunk()` 落盘。
- 同时维护一条 **`pending` 记录**（新增 IndexedDB v2 仓库），记录本次录音的开始时间、格式、采样率、
  已落盘分片数与字节数。
- **先登记再录音**：开始前就写入 pending 记录，避免「正在录但磁盘上没有痕迹」。
- 分片落盘失败**不会静默吞掉**：累计失败次数，保存成功后如实提示
  「有 N 个分片未能落盘，本次已正常保存，但中断恢复能力受限」。

### 5. 中断后恢复：捞回分片 → 合并 → 存成素材

- 进入记录页时检查 pending 记录，若存在且有分片，显示恢复横幅：
  开始时间、分片数、字节数，并提供「恢复并保存 / 丢弃」。
- 恢复流程：`listChunks()` 按 seq 排序 → `new Blob(chunks)` → 复用与正常保存同一条 `persistMemory()` 落盘。
- **如实标注不确定性**：
  - 标题带「（中断恢复）」后缀；
  - 时长无法精确还原（分片不带时间戳），按分片数估算并在提示里说明；
  - 提示用户**到「我的素材」播放确认音质是否完整**。
- 丢弃需要二次确认，且明确「丢弃后无法找回」。

> 计划要求「分块如何恢复、合并、播放必须实测，不能假定任意拼接都可播放」。
> 本实现**不假定**：恢复后主动提示用户播放验证，且该路径已列入待实测清单。

### 6. 纯文字记忆（无需音频）

- 素材列表新增「写一条文字记录」入口。
- 文字记录与录音记忆共用同一套数据结构与导出流程（`audio` 为空即可）。

### 7. 结束后补充元数据

- 录音保存后可直接到「我的素材」→「编辑」，补充标题、正文、录音时间、模糊回忆时间、
  人物、地点、标签、备注。
- 模糊时间以**原文 + 精度**分开保存（某天/某月/某年/某个年代/未标注），
  **不强行解析成精确时间戳**。
- 编辑时**保留 `recordId`、只递增 `revision`**（协议要求：改内容不换 ID）。

### 8. 存储失败不显示「已保存」

- 任何一步失败都进入 `error` 状态并显示原因。
- 错误信息附上**本次录制实况**（分片数、收到字节数），便于区分「没收到数据」与「写入失败」。
- 保存成功提示带实际文件大小，可与预期对照。

## 未验证项目

1. 上述 6 项真机验收。
2. **分片合并后的音频是否可播放**：分片是同一录音流的连续片段，理论上按序拼接等价于完整输出，
   但**必须在目标设备实测确认**（iOS 与 Android 的封装格式不同，风险不同）。
3. 长时间录音（数十分钟）下的分片数量与 IndexedDB 写入压力。
4. 存储配额耗尽时的实际表现。

## 已知问题

1. **恢复录音的时长是估算值**（按分片数），非精确时长——分片本身不带时间戳。
2. 恢复后音频的可播放性未经真机验证（见上）。
3. IndexedDB 升级时若同一域名下有其它标签页打开着旧版本页面，部分浏览器会阻塞升级
   （标准行为，需用户关闭其它标签页）。
