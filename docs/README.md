## archive/ 里有什么

历史文档按用途分开存放，**不参与日常查阅，但保留以便追溯**：

| 位置 | 内容 |
| --- | --- |
| `archive/交接记录/` | A1–A3、B1–B3、C1–C4 共 **10 份阶段交接记录**：每阶段的任务范围、实现要点、修改文件、验证结果、未验证项。**要查"当时为什么这么改"就翻这里。** |
| `archive/安装与启动教程.md`、`archive/启动说明.md` | 已合并为顶层 `安装与启动.md`。 |
| `archive/2026-09-19-验收与发布说明.md`、`archive/2026-09-20-复审复核记录.md` | 已合并为顶层 `验收与复核.md`。 |
| `archive/交付说明.md` | 阶段 A+B 的交付说明，已过时（不含 C 阶段）。 |
| `archive/交付形态与内容基线.md` | 早期关于「正文以什么形态交付」的说明。 |
| `archive/项目审查与待办清单.md` | 某个时间点的项目审查快照与待办清单，结论已被后述验收文档覆盖。 |

## 维护约定

- 完成一个阶段后，**不要把新文档直接堆在顶层**：交接记录统一放进 `archive/交接记录/`，
  只有**长期有效**的文档（协议、调试指南、索引）才留在顶层。
- 已在顶层的内容，**不要再在别处重复一遍**——需要引用就写到本索引里。
- 删改文档前先确认是否被其他文档引用（搜文件名）。
