## 任务编号

**B1．导入 iPhone 录音**

## 完成内容

### 1. 明显的「导入音频」入口

- 资料库「章节」浏览模式下、原「备份与恢复」区块上方新增「导入音频」区块，含「选择文件…」按钮。
- 支持多选（`multiple: true`），文件过滤器覆盖 `wav / m4a / aac / mp3 / ogg / flac / aiff / aif`。

### 2. 支持 WAV 与 iPhone 语音备忘录常见的 M4A/AAC

- 探测（`python_stt/audio_probe.py`）：优先 ffprobe，其次 soundfile，再次 mutagen，最后退回文件头嗅探。输出容器/编码、时长、采样率、声道数。
- 转码（`python_stt/convert_audio.py`）：优先 ffmpeg，其次 soundfile。非 WAV 转码为 **16-bit PCM WAV** 派生文件。
- 转码生成**独立派生文件**，不覆盖原音频：原文件复制为 `<uuid>.<原扩展名>`，派生文件为 `<uuid>.wav`，二者都在应用音频目录。

### 3. 复制到应用管理目录后登记，不依赖源文件

- 导入先把源文件**复制**到应用音频目录（`<uuid>.<ext>`），后续播放/转写都用应用目录内的副本，删除源文件不影响。

### 4. 记录原始文件名、实际格式、时长、文件校验值

- `audio_assets` 新增三列（幂等迁移）：`original_filename`、`source_format`、`file_checksum`（hex SHA-256）。
- `CreateMemoryInput` 与 `RegisterRecordingInput` 同步增加这三个可选字段。
- 音频播放器优先显示**原始文件名**（便于溯源），并标注实际格式。

### 5. 录制时间无法可靠读取时留空，不冒充

- 导入时 `recorded_at` 置空（M4A 的录制时间不可靠），不把导入时间冒充录制时间。

### 6. 导入完成后再启动转写，失败可重试

- 导入复用 A1 的 `register_recording`：登记记忆 + 音频资产 + **待转写任务**（pending）。
- 导入成功后前端自动选中该记忆，用户可在详情页点「开始转写」；转写失败走 A1 的「重新转写」入口，音频与记忆都保留。

### 7. 损坏文件报错，不留伪成功记录

- 探测阶段无法识别格式 → 直接报错，不登记。
- 转码失败 → 清理已复制的临时文件，返回错误，不登记记忆。
- 校验值重复（同一文件已导入）→ 拒绝并提示已导入的记录。

## 已知问题

1. **解码依赖未内置**：应用不自带 ffprobe/ffmpeg/soundfile/mutagen，依赖用户 Python 环境。发布版需明确标注这一外部依赖并提供安装检查（对应验收第 4 条，未做）。
2. **SHA-256 整文件读内存**：超大音频计算校验值可能占内存；当前资料量可接受。
3. **录制时间留空**：M4A 录制时间不可靠故留空，用户需手动补充事件时间。
4. 与 A1–A3 相同：`cargo test` 无法在本机链接执行。
