# 声文素材包协议（Sound-to-Essay Pack Protocol）

协议版本：1
制定日期：2026-09-17
对应任务：B2（定义素材包格式）
状态：待 B3 实现导入后联合验收

---

## 1. 目的与定位

素材包是**手机记录端 → 桌面资料库**之间的**传输容器**，用于把口述记录（含音频与元数据）从手机搬到电脑。

它**不是**完整桌面备份：
- 完整桌面备份（`.svbak`，见 A3）包含整个 SQLite 一致性快照 + 全部音频，用于灾备与恢复。
- 素材包（`.svpack`）只包含**选定要传输的记录**及其音频，用于跨设备搬运。

二者不可混用，也不互相替代。

## 2. 容器格式

### 2.1 外层容器

**推荐** ZIP（deflate），理由：跨平台、流式可读、手机端 Web 原生支持（`CompressionStream`/`DecompressionStream` 或库）。

**允许**等价容器，只要满足：
- 单文件、自包含（manifest + 数据 + 音频都在一个文件里）。
- 能逐文件读出原始字节以计算/校验 SHA-256。
- 不依赖本机绝对路径。

> 本机桌面端因缺少 C 链接器暂用自实现 `.svpack`（与 `.svbak` 同构的二进制容器，见 §7）。**协议字段与 ZIP 版完全一致**，仅容器编码不同；B3 导入时两种容器都应能识别。

### 2.2 包内布局

```text
<包文件>.svpack 或 .zip
├── manifest.json          # 包级清单（必需）
├── records.json           # 记录数据（必需）
├── audio/
│   ├── <asset_id>.<ext>   # 音频文件，文件名即稳定资产 ID
│   └── ...
└── _meta/
    └── source.json        # 来源信息（可选，不含设备唯一标识/账户）
```

## 3. manifest.json

包级元数据与完整性清单。

```json
{
  "formatVersion": 1,
  "packId": "uuid-v4",
  "appVersion": "0.1.0",
  "exportedAt": "2026-09-17T14:30:00+08:00",
  "recordCount": 2,
  "audioCount": 2,
  "records": {
    "path": "records.json",
    "size": 1234,
    "sha256": "<hex>"
  },
  "audio": [
    {
      "assetId": "a1b2c3d4-...",
      "path": "audio/a1b2c3d4-....m4a",
      "format": "m4a",
      "size": 56789,
      "sha256": "<hex>"
    }
  ]
}
```

字段说明：
- `formatVersion`：协议版本，当前为 `1`。导入方校验，不支持的版本直接拒绝。
- `packId`：本次导出的包 ID（uuid-v4）。同一记录**重复导出会生成不同 packId**，但记录 ID 不变（见 §4）。
- `exportedAt`：导出时间，**必须带时区**（ISO 8601 / RFC 3339）。
- `records` / `audio`：各自的路径、字节数、SHA-256，供导入方校验完整性与去重。

## 4. records.json

记录数据数组。每条记录：

```json
[
  {
    "recordId": "r-uuid-v4-stable",
    "revision": 3,
    "title": "外婆的针线筐",
    "body": "正文……",
    "recordedAt": "2026-09-15T10:20:00+08:00",
    "eventDateText": "上世纪八十年代",
    "eventDatePrecision": "decade",
    "people": ["外婆", "母亲"],
    "location": "老宅",
    "tags": ["童年", "手工"],
    "notes": "待核实：具体年份",
    "audio": [
      {
        "assetId": "a1b2c3d4-...",
        "originalFilename": "语音备忘录 001.m4a",
        "sourceFormat": "m4a",
        "durationSecs": 45.2,
        "sampleRate": 44100,
        "sha256": "<hex>"
      }
    ]
  }
]
```

### 4.1 稳定记录 ID 与修订标识

- `recordId`：**稳定记录 ID**，uuid-v4。同一记录无论导出多少次、在哪台设备，ID 不变。导入方据此去重。
- `revision`：**修订标识**，整数，从 1 开始。记录内容每次被修改，导出时 `revision` 递增。
- 同一记录重复导出：`recordId` 相同，`revision` 可能相同（未改动）或更大（已改动）。
- 记录修改后保留 ID、更新 revision——**不得**因为内容变了就换新 ID。

### 4.2 时间字段

- `recordedAt`：录音时间，**带时区**（ISO 8601 / RFC 3339）。手机端录音时记录。
- `eventDateText` / `eventDatePrecision`：**模糊事件时间独立保存**。
  - `eventDateText`：用户填写的原始文本，如 `"上世纪八十年代"`、`"1985年左右"`。
  - `eventDatePrecision`：`year` / `month` / `day` / `decade` / `unknown`。
  - 导入方**不得**把模糊时间强行解析成精确时间戳。

### 4.3 音频条目

- `assetId`：稳定资产 ID，uuid-v4。与包内 `audio/<assetId>.<ext>` 对应。
- `originalFilename`：原始文件名（溯源展示）。
- `sourceFormat`：实际容器/编码（`m4a`/`wav`/...）。
- `durationSecs` / `sampleRate`：探测到的参数，可为空。
- `sha256`：音频文件字节级 SHA-256，用于完整性与去重。

## 5. 安全与隐私约束

1. **不包含**本机绝对路径（包内一律相对路径）。
2. **不包含** API Key、账户配置、设备唯一标识（如 IDFA/序列号）。
3. **不包含** `.svbak` 完整备份里的数据库快照。
4. 音频与正文都是用户口述素材，传输/存储由用户自行控制；协议本身不加密（如需加密由传输层负责，如 HTTPS）。

## 6. 导入语义（B3 实现依据）

1. **追加与去重**：按 `recordId` 去重。本地不存在 → 追加；已存在且 `revision` 相同 → 跳过；已存在且包内 `revision` 更大 → 判定为"更新"。
2. **冲突保留双方**：本地 `revision` 大于包内，或双方 `revision` 相同但内容不一致 → **保留双方并提示**，不静默覆盖。实现：本地保留原记录，包内记录作为新记忆导入（标题加"（冲突副本）"）。
3. **不传播删除**：素材包只携带"要传输的记录"，不携带删除指令。删除只在单端发生，不通过素材包同步。
4. **缺失音频**：记录引用的音频文件在包内缺失或校验失败 → 该记录**不得伪装为完整导入**；导入方应标记"音频缺失"并允许后续补传。
5. **校验值用途**：SHA-256 仅用于**完整性校验与去重**，不构成身份认证。

## 7. 自实现 `.svpack` 容器（本机过渡）

因本机缺少 C 链接器、无法引入 ZIP 库，桌面端样例与 B3 首版导入暂用自实现 `.svpack`：

```
magic "SVPACK1\0" (8B)
manifest_len u32
manifest_sha256 32B
manifest_json manifest_len B
records.json 文件条目（同 .svbak 文件条目格式）
audio/<assetId>.<ext> 文件条目 × N
```

文件条目格式与 `.svbak` 完全一致：`name_len u32 | name | data_len u64 | data_sha256 32B | data`。

**协议字段与 ZIP 版一致**，仅外层编码不同。B3 导入时：
- 读到 `SVPACK1\0` magic → 按 `.svpack` 解析。
- 读到 ZIP 本地文件头 `PK\x03\x04` → 按 ZIP 解析。
- 二者都归一化为同一内存结构后走同一套校验/导入逻辑。

未来在能链接的环境引入 ZIP 库后，`.svpack` 可废弃，协议字段不变。

## 8. 测试样例

见 `tools/pack_samples/`：
- `sample_pack.svpack`：含 2 条记录 + 2 个音频的最小合法包。
- `corrupt_checksum.svpack`：音频 SHA-256 被篡改，用于校验失败路径。
- `unsupported_version.svpack`：`formatVersion=999`，用于版本拒绝路径。
- `missing_audio.svpack`：记录引用了不存在的音频文件，用于缺失音频路径。

样例由 `tools/make_pack_samples.py` 生成（合成音频 + 合成文本，无真实口述素材）。

## 9. 版本演进

- `formatVersion=1`（当前）：首版。
- 未来新增字段必须**可选**（`#[serde(default)]` 语义），保证旧版导入方能跳过未知字段而不是报错。
- 破坏性变更（改字段含义/删字段）必须递增 `formatVersion`，并让导入方明确拒绝。
