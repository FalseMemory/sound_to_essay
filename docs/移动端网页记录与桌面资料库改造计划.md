用途：开发任务交接、分阶段实施、最终验收
目标平台：iPhone 优先，兼顾后续 Android
一、产品目标与边界
将声文扩展为：
手机随时记录个人经历，电脑负责转写、整理、关联素材和编写回忆录。

手机采用可添加到主屏幕的网页应用（PWA）。桌面端保留现有 Tauri 应用。
第一版不追求手机与电脑功能完全一致，优先保证录音可靠保存、可导出、可导入、可恢复。
已确认的产品决定
- 手机以录音、文字记录、补充元数据、播放为主。
- 电脑负责语音转写、AI 整理、资料管理和章节写作。
- 不建设用户账号、云端资料库或自动云同步。
- 手机网页允许部署到 HTTPS 静态托管服务；托管内容仅包括应用代码和公共资源。
- 原始音频、正文及备注默认不上传任何服务。
- 第一版通过文件交换资料，局域网传输安排在后续阶段。
- iPhone 系统“语音备忘录”作为长时间录音和网页录音中断时的备用入口。
- 不承诺网页在锁屏或切换应用后持续录音。
- 不把浏览器本地存储描述为永久备份。
本轮不做
- 微信小程序。
- iOS／Android 原生应用。
- 手机本地 Whisper 推理。
- 手机远程转写和 AI 写作。
- 多设备自动双向同步。
- 在线协同编辑。
- 手机章节编辑器。
二、所有 Agent 必须遵守的实施规则
1. 开始前阅读当前源码和设计文档，核实任务是否已经部分实现，不根据旧对话直接覆盖代码。
2. 每次只完成一个任务编号；验证通过并提交交接记录后，再做后续任务。
3. 保留已有用户数据。数据库升级须有迁移、备份和失败处理。
4. 禁止修改、覆盖原始音频与原始转写。
5. 禁止为了“清理工程”删除用户音频、模型、数据库或历史备份。
6. 不上传真实口述素材，不把用户 API Key 放入网页代码、素材包或测试报告。
7. UI 与业务逻辑分离，避免继续把录音、数据库操作、筛选、章节编辑集中到一个组件。
8. 测试优先使用合成音频和独立测试数据库。
9. 没有实测的能力必须标记为“待验证”，不得将类型检查通过等同于功能通过。
10. 部署到外部托管服务前，完成本地构建与验收准备，再由项目所有者确定托管平台和发布地址。
三、实施顺序
依赖关系：
A：桌面资料安全 → B：音频导入与交换协议 → C：手机记录端 → D：PWA 与恢复 → E：跨端验收
F：局域网传输 为后续可选阶段，不阻塞第一版交付。
阶段 A：先保证桌面端能可靠接收、保存资料
A1．录音与转写解耦
实现要求
- 录音过程中持续或分段写入本地临时音频，避免整段录音只存在内存。
- 停止录音后，先登记音频资产和记忆，再执行转写。
- 转写失败时保留记忆及原始音频，提供重新转写入口。
- 转写任务应具有待处理、处理中、成功、失败等明确状态。
- 应用重启后识别未完成任务，不能永久显示“处理中”。
- 清理未引用音频时保护正在录制、待入库、待转写及可恢复资料。
验收
- 不安装模型时录音，转写失败后仍能找到并播放录音。
- 重启后可以重新转写。
- 录音中异常退出后，能恢复已落盘部分，或明确说明可恢复范围。
- 清理录音不会删除上述资料。
A2．版本与来源保护
实现要求
- 普通“删除历史版本”不得删除原始转写。
- 恢复记忆或章节历史版本只切换当前版本，不制造内容相同的新版本。
- 当前版本切换及搜索索引更新保持事务一致性。
- 删除当前章节草稿后，明确选择剩余版本，或进入无草稿状态。
- 每次 AI 章节生成保存实际使用的记忆 ID、文本版本 ID、模型、处理档位、写作要求及生成时间。
- 旧草稿的来源展示读取生成时记录，不能用当前章节关联列表替代。
- 被历史草稿引用的文本版本不得直接硬删除造成来源断裂。
验收
- 连续恢复相同历史版本，版本数量不增加。
- 修改素材、移除章节关联后，旧草稿仍能定位原输入版本。
- 原始转写不能被普通历史删除操作删除。
A3．编辑保护与完整备份
实现要求
- 记忆正文、元数据及章节草稿在切换、返回、关闭时具备未保存保护。
- 可以采用本地工作草稿自动保存；不要每次输入都创建正式历史版本。
- 筛选条件、选中记忆、选中章节使用独立状态。
- 提供包含数据库、音频及恢复清单的完整备份与恢复流程。
- SQLite 备份使用一致性快照方式，不能假定直接复制活动数据库文件就是完整备份。
- 恢复操作先校验，不静默覆盖现有资料。
验收
- 编辑后切换页面不会无提示丢失内容。
- 按人物筛选后打开记忆，筛选结果保持正常。
- 在独立目录恢复备份后，文字、录音及版本关系均可读取。
阶段 B：桌面音频导入与素材交换协议
B1．导入 iPhone 录音
实现要求
- 提供明显的“导入音频”入口。
- 至少支持 WAV，以及 iPhone 语音备忘录常见的 M4A/AAC 文件。
- 音频复制到应用管理目录后登记为记忆，不依赖原文件永久存在。
- 转码生成独立派生文件，不覆盖原音频。
- 记录原始文件名、实际格式、时长和文件校验值。
- 录制时间无法可靠读取时允许留空或补充，不将导入时间冒充录制时间。
- 导入完成后再启动转写，失败可重试。
验收
- iPhone 导出的真实 M4A 能导入、播放、转写。
- 删除导入源文件后，应用内仍能播放。
- 损坏文件给出错误，不留下伪成功记录。
- 明确验证发布版所需解码依赖，不能只在开发环境测试。
B2．定义素材包格式
在实现手机导出前，先提交协议文档及测试样例。
建议采用 ZIP 容器，包含：
- manifest.json：协议版本、包 ID、导出时间、应用版本。
- 记录数据：稳定记录 ID、修订标识、标题、正文、录音时间、事件时间、人物、地点、标签、备注。
- 音频文件：稳定资产 ID、包内相对路径、格式、大小、校验值。
- 必要的记录与资产关联信息。
协议约束
- 时间使用带时区信息的标准格式；模糊事件时间独立保存。
- 不包含本机绝对路径、API Key、账户配置。
- 区分“传输素材包”与“完整桌面备份”。
- 同一记录重复导出时保留记录 ID。
- 记录修改后保留 ID，同时更新修订标识。
- 第一版导入采用追加和去重；发生内容冲突时保留双方并提示，不静默覆盖。
- 不通过素材包自动传播删除操作。
- 校验值用于完整性和去重，不应描述为身份认证。
B3．桌面素材包导入
实现要求
- 导入前显示记录数、音频数、重复项及冲突项。
- 校验格式版本、文件存在性、大小与校验值。
- 防止 ZIP 路径穿越、异常解压体积及覆盖包外文件。
- 使用临时区域与事务组织导入；失败后能够回滚或安全重试。
- 同一素材包重复导入不产生重复记忆。
- 来源为手机的记录保留来源 ID 和修订信息。
- 缺失音频时不得伪装为完整导入。
验收
- 首次导入、重复导入、修改后再次导入。
- 缺文件、校验失败、不支持的协议版本。
- 导入中断后重试。
- 两个文件名相同但内容不同的音频均能正确处理。
阶段 B 结束条件
即使没有手机网页，用户也能通过“语音备忘录 → 导出文件 → 电脑导入”完成记录流程。
阶段 C：手机网页记录端
C1．独立网页入口与移动布局
实现要求
- 复用合适的类型、协议和纯业务逻辑。
- 浏览器运行路径不能直接调用 Tauri invoke。
- 建立存储、录音、导出等平台适配接口。
- 手机使用单栏页面，主导航建议为“记录、我的素材、设置”。
- 录音作为最突出操作，主要触控目标至少约 44×44 CSS 像素。
- 适配安全区、软键盘、长标题、小屏幕和大字体。
- 第一版不展示桌面章节与旧创作区入口。
验收
- iPhone Safari 无桌面环境依赖错误。
- 小屏幕无主要按钮遮挡、文字重叠或横向溢出。
- Android 浏览器完成基础页面兼容检查。
C2．录音与本地保存
实现要求
- 使用浏览器实际支持的录音格式，运行时探测，不能固定假设为 WebM 或 WAV。
- 明确处理麦克风权限拒绝、设备不可用和录音异常。
- 支持开始、暂停、继续、结束及录音时长显示。
- 音频分块持续保存到 IndexedDB 等合适存储。
- 明确区分录制中、保存中、已保存和中断状态。
- 单条录音分块如何恢复、合并、播放必须实测，不能假定任意拼接都可播放。
- 结束后可立即播放，并补充标题、人物、时间、地点和备注。
- 支持无需音频的纯文字记忆。
验收
- 权限允许与拒绝。
- 暂停后继续录制。
- 连续创建多条录音。
- 保存后刷新页面、关闭重开仍可播放。
- 存储失败时明确提示，不显示“已保存”。
C3．素材管理与导出
实现要求
- 素材列表显示标题、时间、时长及保存／导出状态。
- 支持播放、编辑元数据、单条和多条导出。
- 使用阶段 B 定义的素材包协议。
- 支持系统分享或文件下载，并提供可用的后备方式。
- 导出取消或失败不能标记成功。
- “已导出”不等于“电脑已接收”；没有接收凭据时不得显示后者。
- 默认不在导出后自动删除手机资料。
- 删除记录需要确认，并提供可恢复机制或清晰的不可恢复说明。
验收
- 导出的素材包可在桌面端导入。
- 手机与电脑中的标题、正文、元数据及音频一致。
- 同一包导入两次不重复。
- 导出失败后手机原始资料完整保留。
阶段 D：PWA、离线与中断恢复
D1．离线应用与更新策略
实现要求
- 提供 Web App Manifest、图标、独立窗口显示配置。
- 缓存应用资源，支持首次完整加载后离线启动。
- Service Worker 更新不能在录音或导出过程中强制刷新。
- 应用更新与本地数据库升级不得清空素材。
- 页面展示真实保存位置：“此设备浏览器内”。
- 提供添加到主屏幕及保存副本的简短说明。
- 不加入第三方统计、录音上传或外部 AI 请求。
验收
- 主屏幕启动与 Safari 直接打开均可使用。
- 飞行模式下可以打开、录音、保存、播放。
- 发布新版本后旧资料仍存在。
- 更新提示不会打断正在进行的录音。
D2．iPhone 中断与存储恢复
必须实测的场景
- 锁屏。
- 切到其他应用。
- 来电或音频设备变化。
- 刷新、关闭标签页、强制结束浏览器。
- 磁盘空间不足或存储写入失败。
- 未正常结束的录音恢复。
- 较长录音的内存占用和导出表现。
产品行为要求
- 不支持继续录音的场景，明确显示中断及已保存范围。
- 不允许时长继续增长而实际没有音频。
- 下次启动发现未完成录音，提供恢复或处理入口。
- 记录中断原因及诊断信息，但日志不包含口述正文。
- 清除网站数据会导致本地资料丢失，须在使用说明中讲清楚。
- 若关键中断场景无法可靠恢复，应限制适用场景并保留系统录音导入路线。
阶段 D 结束条件
能够说明“哪些场景已通过、哪些会中断、能恢复多少”，不能仅以录音按钮可用作为完成标准。
阶段 E：发布准备与端到端验收
E1．桌面发布版验证
- 语音转写运行时和资源定位明确。
- 不依赖开发仓库所在目录。
- 不把复制 .venv 当成已完成独立运行时打包。
- 在与源码无关的目录验证录音、音频导入、转写和素材包导入。
- 如果仍需外部 Python，明确标为依赖，提供安装检查；不得宣称完全独立运行。
- 发布版具备可获取的诊断日志。
E2．手机网页发布准备
- 生产构建通过。
- 确认 HTTPS、离线缓存、版本更新与资源路径正确。
- 明确生产域名；浏览器资料按来源隔离，更换域名前必须提供资料迁出说明。
- 托管文件不包含个人素材、数据库、模型或密钥。
- 提供简短的 iPhone 使用与恢复指南。
- 发布地址由项目所有者确认后再部署。
E3．完整使用流程
使用测试素材完成：
1. iPhone 创建录音和文字记忆。
2. 补充人物、地点、模糊时间及备注。
3. 断网关闭并重新打开，检查资料。
4. 导出素材包。
5. Windows 发布版导入。
6. 执行转写，失败后重试。
7. 校订、AI 整理、加入章节。
8. 导出整本 Markdown。
9. 重复导入同一包，确认不重复。
10. 完整备份后在独立目录恢复。
每一步记录预期结果、实际结果和证据。
阶段 F：可选的局域网传输
只有阶段 E 通过后再实施。
- 电脑端提供用户主动开启的本地接收服务。
- 手机通过二维码或一次性配对信息建立连接。
- 设计认证、HTTPS／浏览器访问兼容及明确的接收确认。
- 复用素材包协议，实现幂等传输和失败重试。
- 电脑关闭或网络断开时，手机仍可独立记录。
- 未收到成功确认前，手机不得标记“电脑已接收”。
- 不直接暴露任意文件读写或全部桌面 IPC。
- 不直接同步覆盖 SQLite 数据库文件。
- 第一版只做手机向电脑投递，不扩展为双向编辑同步。
四、每个任务的交付模板
每位 Agent 完成任务后，必须提交：
任务编号：
完成内容：
修改文件：
数据库或协议变化：
执行的检查及结果：
运行时测试及设备：
截图／日志／测试素材位置：
未验证项目：
已知问题：
下一任务的依赖：
回退或恢复方式：
任务状态限定为：
- 未开始
- 实现中
- 自动验证通过，待设备测试
- 设备测试通过，待验收
- 已验收
- 阻塞：注明具体原因
不得将“代码已写完”“构建通过”直接标记为“已验收”。
五、最终交给审查 Agent 的材料
- 本文档的完成状态。
- 当前源码与可定位的改动清单。
- Windows 发布产物及运行依赖说明。
- 手机网页测试入口及构建版本。
- 素材包协议、样例和异常包测试结果。
- 数据库迁移及备份恢复测试结果。
- iPhone 型号、iOS 版本，以及 Safari／主屏幕模式实测记录。
- Android 已测范围与未测范围。
- 所有已知问题，尤其是录音中断、浏览器存储和资料恢复限制。
