# 声文（Voice to Essay）设计文档

> 本文档记录产品方向、设计原则与已知风险修复计划。
> 最后更新：2026-07-29

---

## 一、产品定位

Windows 本地优先的口述史长期资料库。

不是通用语音聊天工具，不是一次性写作助手。
目标用户的首要场景是：**日积月累地记录个人记忆，最终串联成回忆录。**

---

## 二、设计原则（已确认方向）

### 1. 长期资产优先于单次产出
原始音频、原始转写和人工校订都是不可再生的个人资产。
系统设计围绕"多年积累"展开，而非"一次性生成一篇文章"。

### 2. 原始素材不可覆盖
- 原始 WAV 音频文件永久保留在本地。
- 原始转写文本作为档案锁定，任何后续操作都创建新版本。
- AI 整理、人工编辑、摘要、文学化草稿均生成新的 text_version，不覆盖 raw_transcription。

### 3. 本地优先，无服务器
- 不建立服务器、账号体系或云同步。
- 录音默认保存到程序根目录 sounds/，模型保存到 models/，资料库存放到 data/oral_history.sqlite3。
- 用户可自行备份整个程序目录。

### 4. AI 可追溯、可审查
- 每次 AI 输出记录：来源记忆 ID、输入版本 ID、处理类型、LLM 提供商、模型名称。
- 远程 API 仅在用户配置后使用，未配置 API Key 时不发起网络请求。
- AI 输出默认标记为"草稿"，不能覆盖原始档案。

### 5. 先检索、再创作
- 章节生成、经历串联只能基于用户选定并确认的记忆来源。
- AI 不能自行编造完整人生脉络。
- 素材矛盾时必须可见，不能由模型静默裁决。

### 6. 误删可挽回
- 口述资料不可再生，删除操作采用软删除（deleted_at）。
- 资料库删除的记忆可恢复，原始音频不因删除记忆而被自动清理。

## 三、已知风险与修复计划

### 阶段 A：地基修复（当前最优先）

目标：修复阶段 0 遗留问题，保证当前资料库稳定可用。

| 问题 | 修复方案 | 验收标准 |
|---|---|---|
| **编码乱码** | 修复 Rust 和前端中所有用户可见文本的编码。将字符串字面量统一改为 UTF-8 编码的 Rust 字符串，或在外部资源文件中管理。 | 启动后所有按钮、提示、状态信息均正常显示中文，无乱码。 |
| **安装版目录写权限** | 区分开发版与安装版的数据目录：开发版继续用程序根目录（sounds/、models/、data/），安装版（release 模式）默认使用 %APPDATA%/com.voice-to-essay.app/ 下的 sounds/、models/、data/。设置页允许用户自定义这些目录。 | 将应用打包为 .exe 安装到 C:\Program Files 后，录音、模型下载、资料库写入均不触发 UAC 失败。 |
| **SQLite 单点故障** | 每次应用正常退出时，自动将 oral_history.sqlite3 复制为 oral_history.sqlite3.backup（保留最近 3 份，轮替）。同时提供"导出资料库"按钮，可导出为 .sql 或完整目录压缩包。 | 手动删除 .sqlite3 文件后，可从 .backup 恢复；导出文件可在另一台机器上重新导入。 |
| **双轨制混淆** | 明确 deprecation 路线图：新建录音默认进入"资料库"，旧"工作区"保留为兼容入口但不再新增功能。README 和界面提示中说明这一过渡。 | 新用户打开应用默认显示"资料库"视图；旧 .vse 项目仍可打开和编辑，但录音按钮引导至资料库。 |

**阶段 A 完成后暂停，用户手测确认稳定性。**

---

### 阶段 B：AI 整理可控化（阶段 3 调整版）

目标：让 AI 整理真正成为"助手"而非"幻觉源"。

| 问题 | 修复方案 | 验收标准 |
|---|---|---|
| **AI 幻觉不可控** | 阶段 3 只做两种模式："口语校订"（只修错字和口语冗余）和"摘要压缩"（提炼要点）。"文学化改写"模式放到阶段 5，且必须在界面上明确标注为"创作性结果"。 | 用户选择"口语校订"后，AI 输出与原始转写的 diff 中，不应出现新增的事实、日期、人名或对话。 |
| **AI 输出未区分可信度** | 所有 AI 生成的 text_version，version_type 标记为 ai_polish / ai_summary / ai_draft，并在界面中显示来源版本、模型和提供商。 | 用户能一眼看出某段文字是"原始转写"、"人工校订"还是"AI 草稿"。 |
| **多条素材整理时来源丢失** | 多选记忆进行整理时，后端必须记录每条素材的记忆 ID 和版本 ID，前端展示结果时显示"来源于以下 N 条记忆"。 | 整理结果页可点击回溯到每条原始记忆。 |

**阶段 B 完成后暂停，用户手测 AI 整理是否忠实于原始记忆。**

---

### 阶段 C：经历串联与回忆录结构（阶段 4）

目标：从独立记忆中发现关联，但用户始终掌握最终确认权。

| 功能 | 约束 | 验收标准 |
|---|---|---|
| 时间线/人物/地点/主题浏览 | 纯本地检索，不调用 LLM | 浏览时响应时间在 1 秒内 |
| "可能相关记忆"推荐 | 基于 FTS5 关键词重叠 + 共同人物/地点/标签，本地计算候选 | 候选列表必须显示关联依据（如"共同标签：童年"、"同一地点：北京"） |
| AI 章节候选建议 | AI 只接收用户已选定的记忆列表，输出"建议章节名 + 关联原因 + 来源记忆列表" | 用户未确认前，不建立任何正式关联 |
| 章节与记忆关联 | 用户确认后才写入 chapter_memory_link 表；同一记忆可加入多个章节；删除章节不删除记忆 | 章节删除后，记忆仍在资料库中完整保留 |

**阶段 C 完成后暂停，用户确认 AI 串联的经历是否符合真实理解。**

---

### 阶段 D：回忆录编辑器与导出（阶段 5）

目标：从资料库进入"完整作品"。

| 功能 | 优先级 | 验收标准 |
|---|---|---|
| 章节树与提纲 | 高 | 可创建、重命名、调整顺序、删除章节 |
| 章节正文多版本 | 高 | 每次重写生成新版本，显示来源记忆列表 |
| 事实锁定模式 | 高 | 锁定后，AI 只能基于已确认的事实整理，不能引入新素材 |
| Markdown 导出 | 高 | 导出内容与编辑器一致，可选是否附带来源注释 |
| Word / PDF 导出 | 低 | 后续版本再增加 |

**阶段 D 完成后，项目达到可用状态。**

## 四、数据目录规范

### 开发版（debug）
```
sound_to_essay/
├── sounds/              # 原始录音
├── models/              # faster-whisper 模型
├── data/
│   └── oral_history.sqlite3    # 资料库主文件
│   └── oral_history.sqlite3.backup  # 自动备份（保留最近 3 份）
```

### 安装版（release）
```
%APPDATA%/com.voice-to-essay.app/
├── sounds/
├── models/
├── data/
│   └── oral_history.sqlite3
│   └── oral_history.sqlite3.backup
└── projects/            # 旧 .vse 文件（兼容）
```

### 用户可自定义
- 设置页提供"录音目录"、"模型目录"、"资料库目录"三个独立路径选择。
- 修改目录后，应用迁移现有数据（复制而非移动，保留原文件）。

## 五、AI 提示词核心约束（所有阶段通用）

1. **不虚构事实**：不能添加原始素材中没有的事件、日期、地点、人物或对话。
2. **不补全不确定性**：无法确定的细节保留空白或标注"[未确认]"。
3. **矛盾时提出问题**：发现不同素材矛盾时，列出矛盾点，不自行选择一方。
4. **区分事实与创作**：任何文学化改写必须明确标注为"创作性草稿"。
5. **输出可逐段修改**：AI 结果必须可被用户分段编辑和确认。
