## 1. 验收范围与方法

**范围**：E3「完整使用流程」十步（计划文档 §228-239），及支撑它的 A–D 阶段功能现状。

**证据来源**（全部为只读采集，2026-10-06）：
- SQLite 资料库 `data/oral_history.sqlite3`（SQL 只读连接，仅取计数与状态）
- 应用日志 `%LOCALAPPDATA%\com.voice-to-essay.app\logs\shengwen.log`
- 文件系统（备份 / 导出产物）

**证据强度分级**：
- ✅ **客观证据** —— 数据库 / 日志 / 文件可直接核实
- 🔶 **部分证据** —— 功能有执行痕迹，但验收要求中的一个侧面缺失
- ⏳ **待补证据** —— 使用者声称已完成，但电脑侧无法核实（产物可能在仓库之外）

## 5. 已知限制（承接自《验收与复核.md》，逐条仍然有效）

1. 备份 ~1 GiB / 素材包 512 MiB / 手机导出预检 256 MiB 上限（内存读取，无流式归档）。
2. 旧格式 `.svbak` 不自动修复；首见无凭据的旧记录可能产生一次保守冲突副本。
3. 导入失败事务回滚，但已复制的未引用音频保留；恢复失败的准备目录需人工处理。
4. 恢复属**整体替换**，未做与后台写入的全局互斥——不建议工作进行中恢复。
5. 手机端导入音频不转码（刻意设计）。
6. 导入素材的录制时间不自动填写。
7. 手机端仅支持 `.svpack` 容器（桌面端 ZIP 容器未实现）。
8. 发布版依赖外部 Python（faster-whisper + av）与 WebView2，程序与 `resources/python_stt` 必须一起分发。
9. 日志可能含文件路径，不含口述正文，分享前仍应检查。

## 7. 结论

**核心链路「手机记录 → 素材包导出 → Windows 导入 → 转写 → AI 整理 → 章节组织」已通过端到端验证**，
且每一步都有数据库或日志层面的客观证据；素材包的幂等导入、协议三条导入语义（追加 / 跳过 / 更新 /
冲突保留双方）均有自动测试锁定。

**但不能据此宣告 E3 全部验收通过**，原因有三：

1. 第 6 步的「失败后重试」、第 7 步的「AI 生成章节草稿」缺少执行证据；
2. 第 8 步导出产物、第 10 步备份文件不在可核查范围内，需要使用者提供路径；
3. 第 3 步（手机断网重开）本质上无法从电脑侧核实，必须由使用者确认。

**建议结论**：核心链路 ✅；E3 整体 **🔶 有条件通过**——待 §6 清单补齐后可改为正式通过。
E1（独立目录验证）仍为发布前的独立关卡，建议与 §6 一并处理。
